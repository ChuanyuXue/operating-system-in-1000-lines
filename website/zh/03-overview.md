# 我们将实现什么

上一章，我们看到了一个 Rust 函数在 AArch64 上对应的指令。接下来，我们会让 QEMU 启动自己的内核。第一个里程碑是在串口上打印一行字，最终目标则是在用户态的 shell 里输入 `readfile`，读出磁盘上的 `hello.txt`。

## 1000 行代码的操作系统的功能

- **多任务处理（Multitasking）**。多个进程共享一个 CPU 核心。切换进程时，内核保存当前进程的寄存器和栈指针，恢复另一个进程的执行现场，让它从上次停下的位置继续运行。
- **异常处理（Exception handling）**。例如，当用户程序执行系统调用指令 `svc` 时，CPU 会跳到内核设置的异常入口。内核根据异常原因决定如何处理。
- **分页（Paging）**。内核为不同的进程建立页表。两个进程可以使用相同的虚拟地址，各自访问不同的物理内存。
- **系统调用（System calls）**。shell 在 EL0 运行，内核在 EL1 运行。shell 可以通过系统调用请求内核读取文件，或向串口输出一个字符。
- **设备驱动（Device drivers）**。我们会用 PL011 串口收发字符，用 VirtIO 块设备按扇区读写虚拟磁盘。
- **文件系统（File system）**。块设备只认识扇区，shell 使用的却是文件名。内核需要识别磁盘映像里的文件条目，才能按名字查找和更新文件内容。
- **命令行 shell**。shell 从串口接收命令。例如，`readfile` 会请求内核读取 `hello.txt`，再把返回的内容显示在终端。

## 未实现的功能

- **中断处理**。串口输入和磁盘 I/O 都采用轮询。例如，发出磁盘请求后，驱动会反复检查设备是否已经完成请求。上一节提到的 `svc` 属于同步异常，由执行这条指令直接触发。
- **定时器处理**。本书采用协作式调度。正在运行的进程需要主动让出 CPU，其他进程才有机会运行。如果一个进程一直在计算，内核没有时钟中断来抢占它。
- **进程间通信**。管道、Unix 域套接字和共享内存留作扩展。
- **多处理器支持**。我们只启动一个 CPU 核心，因此可以先专注于一个核心上的进程切换。

## 源代码结构

后续章节会逐步搭建下面的 Rust 工程。读这张目录图时，可以先找到两个入口：内核在启动后管理内存和设备，shell 是由内核加载的用户程序。

```text
├── Cargo.toml           整个工程的 Cargo 工作区配置
├── .cargo/config.toml   AArch64 裸机编译目标
├── kernel/
│   ├── Cargo.toml       内核的构建配置
│   ├── kernel.ld        内核的入口地址和内存布局
│   └── src/main.rs      Rust 内核入口
├── user/
│   ├── Cargo.toml       用户程序的构建配置
│   ├── user.ld          用户程序的内存布局
│   └── src/
│       ├── lib.rs       系统调用封装，供用户程序使用
│       └── bin/shell.rs 命令行 shell 的入口
├── disk/                打包进磁盘映像的示例文件
└── run.sh               构建并启动 QEMU
```

> **与原书对照**　目前教程仓库根目录里的 `kernel.c`、`user.c` 和 `shell.c` 是原书的参考实现。可以从 `shell.c` 的 `readfile` 命令开始，跟到 `user.c` 的系统调用封装，再看 `kernel.c` 怎样按文件名查找数据。Rust 版会保留这条调用路径。

想知道这个示例最终会读到什么，可以先在教程仓库根目录查看用于制作磁盘映像的文件：

```sh
cat disk/hello.txt
```
